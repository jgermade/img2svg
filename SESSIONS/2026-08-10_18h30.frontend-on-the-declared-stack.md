# The page, on the stack it was supposed to be

**2026-08-10 18:30** — First note that touches only `web/`. Nothing in `src/`
moves, no snapshot changes, the CLI is not involved.

Plan. Nothing below is implemented yet.

---

## The gap

[STACK.md](../STACK.md) declares the frontend: **Vite + OXC + Preact**, with
`static/`, `src/assets`, `src/components`, `src/services`, `src/views` and
`index.html` as the entrypoint — and the rule that a component may import only
from `src/components`.

`web/` is none of that. No `package.json`, no build, no dependency: four files
served as they are.

| STACK.md | `web/` today |
| --- | --- |
| Vite + Preact | 425 lines of hand-written HTML, 633 of imperative JS |
| `src/components` / `src/views` | one `ui` object with **62** `getElementById` |
| `src/services` | the store is three module-level `let`s in `app.js` |
| `static/` (publicDir) | `img2svg.svg`, dropped into `web/` by CI |

The numbers are the argument. **66** ids in the markup, **62** entries in `ui`,
**38** `addEventListener` calls, **21** `.field` blocks that differ only in
label, range and prose. Nine of those are the same slider — write the value into
a `<b>`, then debounce a convert — copied nine times. Five are the same
checkbox-enables-the-field-next-to-it pair. Two are the same three action
buttons, wired over a pair because each `<aside>` has its own.

Adding one option today means: an id in `index.html`, an entry in `ui`, a
listener, and a line in the options builder. Four places, in two files, and
nothing fails if you miss one.

## What is good and has to survive

This is a restructure, not a redesign. The page works, and several things in it
were arrived at deliberately across earlier sessions:

- the wasm lives in a worker, pixels are **transferred once** and stay there, and
  each settings change sends only the options;
- replies from a superseded request are dropped by id;
- skeletons on load, and on re-convert the previous SVG is **dimmed rather than
  replaced** — the reason the `stale` class exists;
- the 120 ms debounce, and the 180 ms hold at 100% so the bar does not vanish
  like a failure;
- the fit tolerance resets to the fitter's own default on switch (0.75 polygon,
  1.5 spline). The last session measured why: carrying 0.75 over to the spline is
  precisely the value that makes it look broken;
- `#pixelart` / `#photo` in the URL, with `#curves` aliased to `photo` because
  that tab had that name before it had an engine;
- the a11y: `tablist` with arrow keys, `aria-selected` / `aria-controls`,
  `role="progressbar"` with a live `aria-valuenow`, a drop zone reachable by
  keyboard with Enter and Space, skeletons `aria-hidden`.

All of it is re-implementable and all of it is losable in a rewrite. It is a
checklist below, not a hope.

## What the stack means, concretely

STACK.md names three tools and does not say how they fit. These are the readings
I intend to implement; the ones worth a second opinion are collected at the end.

**Preact + Vite.** `@preact/preset-vite` for JSX and HMR that preserves state.
The Babel-free route (esbuild/oxc with `jsx: "automatic"`,
`jsxImportSource: "preact"`) also works and drops a dependency, at the cost of
prefresh. One dev dependency is worth keeping the reload from wiping the loaded
image on every edit.

**OXC.** `oxlint` in `npm run lint` and in CI from day one — that is the part of
Oxc with an unambiguous job here. Oxc *as the bundler* means `rolldown-vite` in
place of `vite`; it is a drop-in on paper and I will verify it against the wasm
and worker cases before committing to it, because those are exactly where a
bundler swap shows. Plain Vite is the fallback and the swap stays one dependency
away.

**The wasm stays where it is.** `web/pkg/` is wasm-pack output: gitignored except
the committed `img2svg.d.ts`, and a build *input* for the page, not source. The
generated glue loads the binary through `new URL(..., import.meta.url)`, which
Vite understands and emits as a hashed asset; the worker is instantiated the same
way, which is Vite's supported form. Both need checking in a real `vite build`,
not just in dev — that is step one below.

**Base path.** The site is published to GitHub Pages from this repo, so it is
served under `/img2svg/`, not at a domain root. Today's page survives that by
using relative URLs throughout. Vite must therefore be configured with
`base: "./"`; the default `/` would produce a site that works locally and
404s every asset in production. This is the single most likely way to break the
deploy and it does not show up until release.

**The logo.** `img2svg.svg` lives at the repo root and CI copies it into `web/`.
It becomes `web/static/img2svg.svg` (publicDir), copied by a `prebuild` npm
script rather than by a CI step, so local and CI do the same thing.

**CSS.** `style.css` moves to `src/assets/style.css`, imported once, unchanged.
Its 562 lines are written against the current class names, and splitting them
into per-component modules is a second migration with its own risk. This one is
about structure; the stylesheet stays global and the class names stay put.

## The two panels: share the widget, not the field

The panels are visibly repetitive and it is tempting to factor out a
`<ToleranceField>` used by both. That would be wrong, and the code already says
why. Pixel-art tolerance is 0–48 in channel distance; photo tolerance is
0.01–0.2 on a perceptual scale where black to white is 1. Same word, two
vocabularies — which is exactly the reason `MODES` keeps a `report` per mode
today instead of one function with half its fields empty.

So `src/components` gets **generic widgets**: a range, a number box, a gated
field. Each panel keeps its own labels, its own bounds and its own prose,
verbatim. What disappears is the wiring, not the copy.

The copy in particular is not up for editing in this session. The Spanish in
those `<small>` blocks was written carefully — a restructure does not get to
reword it, and a diff that does is a diff nobody can review.

## The store

`src/services/converter.js`, built on `@preact/signals`: the worker, the request
counter, the loaded image's metadata, the last SVG, progress and error. Methods
`load(blob, name)`, `convert(engine, options)` and `reset()`, with the debounce
inside so no caller has to remember it — same reasoning as throttling progress
inside `Progress` on the Rust side rather than at each call site.

Two pieces of state live in the DOM today and need naming, because they are where
a re-render fights the user:

- **`pixelartReport` writes back into the `scale` field.** With auto-scale on, the
  detected cell size is pushed into the manual input so that unchecking it starts
  from the right number. The store publishes `detectedScale`; the panel displays
  it and seeds the manual field from it. Writing a *result* into a controlled
  input must not schedule another convert, or the page converts forever.
- **`syncFit` resets the tolerance slider** to the default of the fitter just
  chosen, and hides the field entirely for `pixel`. Behaviour, not decoration —
  see above.

## CI, docs and ignores

- **`build.yml`**: add `actions/setup-node`, `npm ci`, `npm run lint`,
  `npm run build` in `web/`. Order matters — wasm-pack must run first, because
  `web/pkg/` is an input to the bundle. The `cp img2svg.svg web/` step goes away
  (the `prebuild` script does it), and the uploaded artifact path becomes
  `web/dist`.
- **`release.yml`**: unchanged. It downloads the artifact named `web` into a
  `web/` directory and deploys that; what changes is only what is inside it.
  Worth confirming after the first release build that the deployed tree is the
  built site and not a directory with `src/` in it.
- **`.gitignore`**: add `node_modules/` and `/web/dist/`; `/web/img2svg.svg`
  becomes `/web/static/img2svg.svg`. `/web/pkg/*` and the `.d.ts` exception stay
  exactly as they are — that mechanism is load-bearing and documented.
- **`scripts/web-smoke.mjs`** keeps working untouched (it reads `web/pkg/`
  directly), but its comments name `web/worker.js` in three places. That file is
  the only thing pinning the field list the worker copies, so the pointer has to
  stay accurate.
- **`docs/development.md`**, "The web build": wasm-pack first, then
  `npm install` and `npm run dev`. The note that the wasm must be served over
  HTTP stays true; the reason becomes "the dev server does it for you".
- `web/pkg/package.json` already exists — wasm-pack writes it. It is unrelated to
  the new `web/package.json` and must not become a workspace member; `pkg/` is
  generated and ignored.

## What this buys, and what it costs

It changes nothing for the user: same page, same pixels. What it buys is that a
new option becomes one entry in one panel; that the two panels stop drifting
apart by hand; and that the state stops living in the DOM, where today a result
writes into an input and a checkbox writes into another input's `disabled`.

What it costs is real and should be said: a Node toolchain in a repo that had
none, a build step between the source and a page that could previously be opened
with a static server, and `node_modules` in CI.

The risk is concentrated in one place. `web/` is the only surface here with no
automated test — the Rust side has fifteen snapshots and a corpus, and
`web-smoke.mjs` exercises the wasm, not the page. So this migration is a rewrite
of the untested part. `npm run build` catches a broken import, `oxlint` catches
the undefined and the unused, and everything else is the checklist above, walked
once, deliberately.

The first two steps are deliberately inert, in the spirit of the previous
session's `Vertex` step: getting Vite to serve and build the page *unchanged*

something about this stack does not fit the wasm, it shows there — with nothing
else in flight to confuse it.

## Decisions to confirm before starting

1. **JS + JSX, or TypeScript?** Recommendation: JSX. The counter-argument is real
   — `web/pkg/img2svg.d.ts` is committed precisely to freeze the API JavaScript
   sees, and today nothing on the page consumes those types, so `tsc --noEmit`
   would tie the worker's field copying to the declared shape at build time. If
   that appeals, the cheap version is TS in `services/` only.
2. **`rolldown-vite` (Oxc through the whole build), or plain Vite + `oxlint`?**
   Recommendation: start plain, lint with Oxc, swap later if wanted.
3. **`@preact/signals` for the store**, or a hand-rolled subscribe?
   Recommendation: signals.
4. **One global stylesheet**, or CSS modules per component? Recommendation:
   global now, as argued above.

# Extension — 2026-08-10 18:47

**STACK.md dropped the `src/` layer, and asked whether `pkg/` belongs in
`static/`.** The layout above is superseded by the one here; everything else in

## The layout, flattened

`src/` is gone — the folders hang straight off `web/`, which is the Vite root.

```
web/
  index.html            vite root entrypoint
  package.json
  vite.config.js        base: "./", publicDir: "static"
  main.jsx              mounts <App/> — see the open points below
  static/               copied verbatim, served by URL: img2svg.svg
  assets/               imported and hashed: style.css
  components/           presentational only; import nothing but each other
  services/             worker.js, converter.js, format.js
  views/                App, Header, Workspace, Preview, the two panels, Footer
  pkg/                  wasm-pack output — imported, not served
```

The whole Node project lives in `web/` — `package.json`, `vite.config.js`,
`node_modules/` — so the repository root stays Rust's. `publicDir` resolves
relative to the Vite root, so `static` needs no path juggling.

## `pkg/` does not go in `static/`, and the reason generalises

The line between those two folders is **imported** against **served**. `static/`
is `publicDir`: copied verbatim, never processed, referenced by absolute URL from
the site root, and Vite documents that you should not import from it.

`pkg/` is imported. `services/worker.js` opens with a static
`import init, { convertRgba, convertPhoto } from "./pkg/img2svg.js"`, and the
wasm-pack glue reaches for the binary with

```js
module_or_path = new URL('img2svg_bg.wasm', import.meta.url);   // pkg/img2svg.js:565
```

which Vite rewrites into a hashed asset **only for files that go through its
pipeline**. Inside `publicDir` that file does not. Moving `pkg/` there costs
three things:

- the static import stops resolving. It becomes a dynamic `import()` of an
  absolute `/pkg/img2svg.js`, which collides head-on with the `base: "./"` that
  Pages needs under `/img2svg/`: the path would have to be assembled from
  `import.meta.env.BASE_URL` by hand, inside the worker;
- the `.wasm` loses its content hash. Pages serves fixed headers, so a stable
  name over a binary that changes every build is a stale cache waiting to happen;
- it drags the `.d.ts` guard along: `.gitignore`, the
  `git diff --exit-code -- web/pkg/img2svg.d.ts` step in `build.yml`, the paths
  in `scripts/web-smoke.mjs`, the docs. That mechanism works and is written down;
  relocating it buys nothing.

Left where it is, Vite emits the wasm as a hashed asset that resolves under any
base, and **nothing in CI changes on its account** — which shortens the CI
section above by exactly one worry: the Node steps and the artifact path still
change, the `pkg` handling does not.

The logo is the legitimate `static/` case: referenced by URL from `<head>` and
from the header `<img>`, never imported.

## Open points in STACK.md

Not blocking, but they are what a reader trips on:

- line 14 still reads *"can use src/components and src/services"*, left over from
  the previous layout;
- line 15 gives `index.html` with no prefix while every other entry carries one;
- there is no slot for the JS entrypoint, `package.json` or `vite.config.js`.
  This plan puts all three in `web/`, beside `index.html`;
- `assets/` and `static/` are now siblings and read as near-synonyms. The
  distinction is the same one that decides `pkg/`, so saying it once covers both;
- `pkg/` is not listed at all, though it is the one folder with a rule attached.

# Walkthrough

**2026-08-10 19:35** — Landed, on the four recommendations: JSX rather than
TypeScript, plain Vite with `oxlint`, `@preact/signals`, one global stylesheet.

## What landed

`web/` is a Vite + Preact project: 633 lines of imperative JS and 425 of
hand-written markup became 1,398 lines across 19 modules — 8 components, 3
services, 7 views and an entrypoint. The stylesheet moved untouched and not one
class name changed, which is what let the whole thing be checked against the old
page by looking at it.

The numbers that made the case are gone: **62** `getElementById` and **38**
`addEventListener` are now zero. The nine copies of *«write the value into a
`<b>`, then debounce a convert»* are one `<Range>`; the five copies of *«a
checkbox enables the control beside it»* are a `<Check>` next to whatever it
gates; the two identical action rows are one `<Actions>` used twice.

**`web/services/converter.js` is the only module that talks to the worker.** It
owns the request counter, the transferred pixels, the stage table, the 120 ms
debounce and the 180 ms hold at 100%. Views read its signals. Nothing above it
knows there are messages.

**Who debounces is a property of the control, not of the setting.** A range, a
number box and a colour picker send `{ continuous: true }` with their change; a
checkbox and a select do not. That is the distinction `app.js` made by hand at
twenty call sites, choosing `schedule()` or `convert()` each time.

## Three things worth recording

**1. The `pkg`-in-`static` question had a load-bearing answer, and the build
proved it rather than the argument.** `vite build` emits
`assets/img2svg_bg-<hash>.wasm` and resolves it from the worker chunk against
`self.location.href`; served under `/img2svg/` every asset comes back 200. In
`publicDir` none of that happens — the import would have had to become a dynamic
one against `import.meta.env.BASE_URL`. The plan said this; the build is what
settled it.

**2. A latent bug in the old page, found by having to name the state.** Writing
`reset()` as a store method made it obvious that `app.js` never invalidated the
in-flight request: press *Otra imagen* mid-convert and the `done` that arrives
afterwards runs `render()`, which reads `source.bytes` from a `source` that reset
set to `null`. A `TypeError`, on a button that is always enabled. The store bumps
the request id in `reset`, so the reply is discarded like any other stale one.

**3. The stats line had to remember which engine wrote it.** `app.js` computed
the report *once*, when the result arrived, so it always used the mode current at
that moment. A component recomputes on every render, and between switching tabs
and the new conversion landing that would read a pixel-art result with the photo
vocabulary — `lienzo undefined×undefined`. The store therefore publishes
`engine` alongside `result`, and the preview reads the report with the vocabulary
of whatever produced it.

## Verified rather than assumed

The plan said this migration rewrites the only surface with no automated test,
and that the net would be `npm run build`, `oxlint` and a checklist walked by
hand. The checklist was walked by a CDP driver instead —
`.tmp/scripts/look.mjs`, still out of the repo and out of CI, as every note since
the `.d.ts` one has said. It drives headless Chrome over the **built** site,
drops a real `File` on the document, and asserts 30 things: the tabs and their
arrow keys, `#curves` still landing on photo, the detected scale coming back into
the manual field, the deviation slider appearing only for a fitter that reads it
and resetting to 1.5 for the spline, the bar arriving and leaving, the stats
changing vocabulary between modes, copy, reset, and paste.

Two of its checks failed on the first run and **both were the test, not the
page** — worth writing down because the second one was nearly recorded as a bug:

- *«the bar is gone when it finishes»* was read before the deliberate 180 ms hold.
- *«moving a slider re-converts»* compared the stats before and after. On a
  two-colour sprite, tolerance 0, 12 and 40 give byte-identical output, so the
  string was rightly the same. A `MutationObserver` says the line was rewritten,
  and the real proof that the value reaches the wasm moved to the photo panel
  over a gradient: **8 colours / 15 regions at 0.045, 4 and 4 at 0.2.**

`scripts/web-smoke.mjs` still passes untouched: it reads `web/pkg/` directly, and
`pkg/` did not move. Its comments now point at `web/services/worker.js`, since
that file is what pins the field list it checks.
