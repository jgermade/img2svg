## The finding, before any code

Both previous notes justified the `.d.ts` guard the same way: *"the JS API stops
being able to break in silence — photo mode just added a second result type to
it"*, and *"ten lines against an afternoon, and phase 4 is about to change the JS
API twice"*. Phase 4 has now made one of those two changes. Checking what it did
to the emitted `.d.ts` is what this section is:

- **`PhotoConversion`** — a whole new class, every getter described. A committed
  `.d.ts` would have shown it.
- **`fit` and `fitTolerance`** — two new option keys, read by `read_fit`
  ([wasm.rs:234](../src/wasm.rs#L234)) and written by the page
  ([app.js:250](../web/app.js#L250)). The signature is
  `convertRgba(width, height, data, options: any)`. **The `.d.ts` did not change
  by one byte.**

So the guard as specified protects the half of the API that was never the
fragile half. Result types are Rust structs: rename a getter and the compiler
walks you to it. The option bag is the opposite — read by string key through
`Reflect::get`, and a typo does not fail, it silently takes the default. That is
the half that can break in silence, and `any` is precisely the type that says
"no promises here".

Ninth in a row, and the same shape as the other eight: it surfaced from looking
at the artefact the plan was about, not from reasoning about it.

### What follows from it

The guard is still worth its ten lines — it freezes a real surface — but it is
not the thing that was being bought. Two additions make the purchase match the
description, and they are different in kind:

1. **Declare the options in TypeScript.** `typescript_custom_section` with a
   `PixelOptions` / `PhotoOptions` interface, and `unchecked_param_type` on the
   parameter so the signature reads `options: PixelOptions`. Both attributes
   exist in the pinned wasm-bindgen 0.2.127. This makes the keys *declared*, so
   changing them moves the `.d.ts` and the guard fires.

   It does **not** make them *checked*: the interface is hand-written TS living
   in a Rust string, so a key added to `read_config` and not to the interface
   still changes nothing. It converts an invisible omission into one that is
   visible in review. That is less than it sounds and more than zero, and it is
   worth being explicit that the difference exists rather than letting the guard
   imply a guarantee it has not got.

2. **The Node script is what actually checks the keys.** It can pass
   `{ fit: "polygon", fitTolerance: 8 }` and assert the output *changed*. No
   declaration can do that, and it is the check that would have failed if
   `read_fit` had never been wired. The two items chosen for this session turn
   out to be one item and its complement, which is a good reason to do them
   together.

## 1. The guard

**`.gitignore` first, and it has a trap.** The file currently excludes the
directory: `/web/pkg/`. A negation cannot re-include a file whose parent
directory is excluded — git never descends into it, so `!/web/pkg/img2svg.d.ts`
would do nothing at all, silently. The contents have to be excluded instead:

```gitignore
/web/pkg/*
!/web/pkg/img2svg.d.ts
```

Then commit the generated `web/pkg/img2svg.d.ts` as it stands today, and add to
`build.yml`, immediately after **Compilar a WebAssembly**:

```yaml
- name: La API de JS no cambia sin querer
  run: git diff --exit-code -- web/pkg/img2svg.d.ts
```

`--exit-code` prints the diff before failing, so the log says what moved.

**Two things worth knowing before it lands**, both accepted rather than solved:

- The file contains the whole `InitOutput` block — `__wbindgen_malloc`,
  `__externref_table_alloc`, every internal export. The guard will therefore fire
  on things that are not API changes, most predictably **a wasm-bindgen bump**,
  which rewrites that block. That is arguably correct (the shipped surface *did*
  change) but it is noise, and the answer is a line in `docs/development.md`
  saying: rebuild, read the diff, commit the file. Filtering the block down to
  the public part would need a script that itself can rot, for a failure mode
  that costs one minute.
- It only catches drift on a machine that ran the wasm build. Locally that means
  `PATH="$HOME/.cargo/bin:$PATH"`, still.

## 2. `scripts/web-smoke.mjs`

The look-at-it loop, in the cheap form the last note asked for and rebuilt from
memory four times. Node only — no Chrome, no dependencies, no PNG decoding
(the browser is what decodes, so the wasm has no image codecs in it).

- Reads `web/pkg/img2svg_bg.wasm` as bytes, imports `web/pkg/img2svg.js`, calls
  `init({ module_or_path: bytes })`. That is the whole reason it needs no server:
  the default path fetches a URL, and handing it bytes skips that.
- Builds a synthetic RGBA buffer in JS, same idea as the ASCII sprite in
  `tests/golden.rs`: a few flat blocks, a diagonal, a one-pixel line.
- Calls `convertRgba` and `convertPhoto` and asserts, in order of what each one
  is for:
  - the SVG is non-empty and starts with `<svg`;
  - **every field `worker.js` copies is defined** — that list
    ([worker.js:17-42](../web/worker.js#L17-L42)) is the actual coupling between
    the page and the wasm, and a renamed getter turns into `undefined` there
    rather than into an error;
  - **`fit: "polygon"` with a large tolerance emits fewer path vertices than
    `fit: "pixel"`** on the same buffer. This is the assertion the `.d.ts` guard
    cannot make: it proves the option key is *read*, not merely declared.
- Non-zero exit on any failure, and it prints the stats line either way, because
  the point of the loop is to be looked at.

**It goes in CI.** The previous notes said the look-at-it loop must stay out, and
that was about the CDP driver — Chrome, screenshots, questions no assertion
answers. This one is Node, the wasm is already built two steps earlier, and it is
a couple of seconds. The CDP driver stays out, as before.

# Walkthrough

**2026-08-10 17:20** — All four items landed, including the typed options. Two
more things the plan had wrong, both found in the doing.

## What landed

**The options are typed.** `typescript_custom_section` gives `FitOptions`,
`PixelOptions extends FitOptions` and `PhotoOptions extends FitOptions`, and
`unchecked_param_type` puts them in the signatures — the `.d.ts` now says
`convertRgba(..., options: PixelOptions)` where it said `any`. Both attributes
work on the pinned wasm-bindgen 0.2.127. Each interface sits **next to the
reader that implements it**, not in a block of its own: they are two hand-written
lists saying the same thing and the compiler cannot reconcile them, so the only
remaining mechanism is that whoever adds a key downstream has the interface in
front of them.

**The `.d.ts` is committed and CI diffs it**, right after the wasm build.

**`scripts/web-smoke.mjs` is in**, and in CI. Node only — the `.wasm` bytes go
straight into `init()`, so no server and no Chrome. It boots the wasm, checks
every field `worker.js` copies, and asserts the option keys are read.

## What the plan had wrong

Tenth in a row, and two of them again.

**The `.gitignore` fix was not enough, because wasm-pack writes its own.** The
note had the first trap right — exclude `/web/pkg/*`, not `/web/pkg/`, because
git will not descend into an excluded directory to see the `!` exception. It
missed that wasm-pack drops a `web/pkg/.gitignore` containing `*`, and the deeper
file wins over the root one. So the exception is inert as written and the first
add needed `-f`. It works from there — ignore rules stop applying to a tracked
file — but "the negation re-includes it" is not why, and someone regenerating
this from the note alone would have concluded the guard was set up when it was
not.

**"Every field `worker.js` copies is defined" is false for three of them.**
`background`, `checkerCell` and `checkerCoverage` are `undefined` on any input
with no background and no checkerboard, which is most inputs. Asserting they
carry a value would have meant building fixtures for both, to check a rename.
Split instead: `campo in base` for all of them — wasm-bindgen getters live on the
prototype, so a renamed one stops being `in` the object, which is exactly the
failure being hunted — and `!== undefined` on top for the ones that must always
carry a number. Strictly more coverage than the plan asked for, and no fixtures.

## Verified rather than assumed

**The script was made to fail.** Renaming the `"polygon"` arm of `read_fit` to
`"polygonal"` — the exact silent drift this session exists for — rebuilt, and:

```
FALLA  fitTolerance llega al ajustador (107 -> 107 cifras de path)   [pixelart]
FALLA  fitTolerance llega al ajustador  (51 -> 51 cifras de path)    [photo]
```

Two failures, one per entry point, everything else green. Reverted, rebuilt, back
to `107 -> 44` and `51 -> 35`.

**The generated `.d.ts` is byte-for-byte reproducible.** After breaking,
rebuilding, reverting and rebuilding again, `git diff --exit-code` came back
clean. Worth checking before trusting a guard to a generator: one that emitted a
timestamp or a hash-ordered block would fire at random and be turned off within
the week.

`cargo fmt --check`, `cargo clippy --all-targets -- -D warnings` and the full
suite pass, corpus included (6 tests, run rather than skipped).
