## What landed

**`Fit::Polygon` is in, on all three surfaces.** Ramer–Douglas–Peucker per half
edge, tolerance in pixels, `--fit polygon` on both subcommands, a `fit` key in
both wasm readers and a control in both web panels. The default is still
`Pixel`, so the eleven pixel-art snapshots did not move — and neither did the
four photo ones, which was the point of the shape the change took.

The measured win, on one corpus image against 30,231 vertices and 117 KB:

| tolerance | vertices | SVG |
| --- | --- | --- |
| 0 | 30,231 | 117 KB |
| **0.75 (default)** | **19,261** | **103 KB** |
| 1.0 | 12,036 | 85 KB |
| 1.5 | 10,943 | 82 KB |
| 3.0 | 9,059 | 76 KB |

`0` reproducing the pixel fitter byte for byte is not a coincidence worth
skipping past: RDP only ever *selects* vertices, so with no tolerance it selects
all of them and the two fitters are provably the same code path. That is a test.

## The restructure, and why nothing moved

The previous note found that the fit ran on the assembled ring and had to run per
half-edge. It does now: `fit::Fitted` fits every `EdgeId` once, and only then
chains rings out of fitted edges. `Regions::ring_points` and the fitted-edge
assembly are the same function now, `region::chain`, because the rule about which
point repeats where is subtle enough that having it twice is how it goes wrong.

The reason all fifteen snapshots survived a change to the middle of the pipeline
is one deliberate extra step: after assembling, vertices lying **exactly** on the
line between their neighbours are dropped. That is not fitting — the drawn line
is identical — so it is safe across a node in a way RDP is not, and it means the
pixel fitter emits exactly what it emitted before. Getting a structural change to
be byte-for-byte inert is worth the extra pass on its own; it is the difference
between "the tests pass" and "the tests could not have failed for any other
reason".

`tests/fit.rs` checks the seam directly, on the emitted document rather than on
internals: **every interior segment is drawn by exactly two faces, with the same
endpoints**. It was verified to fail — reintroducing the per-ring fit reports
`el segmento (3, 2)-(3, 3) lo dibujan 1 caras, no dos`. A regression test nobody
has seen fail is a guess.

## What this session found that the plan had wrong

Eighth in a row, and for once two of them.

**`crispEdges` was filed under `spline` and belongs to `polygon`.** The plan
listed the hardcoded `shape-rendering="crispEdges"` as something the Bézier
fitter would have to make conditional. It is not the curve that breaks it, it is
the *oblique segment*: crisp rendering turns off antialiasing, so the first
diagonal the polygon fitter straightens gets drawn as the same staircase it just
removed, and the fit looks like it did nothing. Filed one phase too late, and it
would have shown up as "the polygon fit produces smaller files that look
identical", which is a confusing thing to debug. It is conditional now.

**RDP cannot tell a staircase step from a one-pixel detail, because they are the
same thing.** The tolerance was going to be chosen so that diagonals straighten
(a 45° step sits 0.707 from its chord) while real one-pixel detail survives (a
bump on a straight edge sits 1.0). That gap is not real. A shallow staircase —
three across, one down — sits 0.95 from its chord, which is a bump for all
practical purposes. Only *context* separates an artefact from a feature, and RDP
sees no context. Most of the compression lives in exactly that overlap, which is
why the knee of the table is between 0.75 and 1.0.

So the default is 0.75: the smallest value that does anything at all, chosen for
being conservative rather than for being a good trade. Anyone who wants the file
smaller sets the tolerance and knows what they are buying.

**And a related overclaim, caught by a test that failed for the right reason.**
"A detail taller than the tolerance survives" is false. RDP measures against
whatever chord the recursion currently holds, not against a vertex's neighbours,
so a chord coming from far away swallows a bump that in isolation sits 1.0 away.
The test was written asserting the false version, failed, and was rewritten to
assert what is actually guaranteed: the ceiling. **No point of the contour ends
up further than the tolerance from what gets drawn.** That is the whole contract,
and it is now the test.

## What is left

```
[ ] Fit::Spline   corners, tangents, Schneider (+ node tangents)
[ ] .d.ts guard in CI
[ ] Real progress in the photo worker
```

`Fit::Spline` is now only the mathematics. The plumbing the plan listed alongside
it is done and paid for by the polygon: per-half-edge fitting, endpoints pinned
at nodes, `crispEdges` conditional, and a path writer that emits more than `h`/`v`
(it emits `l`; the spline adds `C`). What remains of the plan's list is tangent
continuity across a node — correct at a three-region junction, visible at a node
that is geometrically smooth — and the fix, if it matters, is to estimate the
tangent at shared nodes once and constrain both chains, which the IR already
makes reachable.

Leftovers not tied to a phase, unchanged from the previous note except that the
first is now more urgent, because this session changed the JS API again:

- **`.d.ts` guard.** CI already builds the wasm; it needs a committed
  `web/pkg/img2svg.d.ts` and a `git diff --exit-code`. Ten lines. Note that
  `web/pkg/` is currently gitignored, so the guard has to un-ignore that one file.
- **Real progress on the page**, instead of the indeterminate bar.
- **Homebrew Rust shadows rustup locally** — anything touching the web build
  needs `PATH="$HOME/.cargo/bin:$PATH"`. Still true, still not fixed.
- **The look-at-it loop is still not in the repo.** Rebuilt a fourth time this
  session, in the cheapest possible form: a Node script that loads
  `web/pkg/img2svg.js`, passes the `.wasm` bytes to `init()` and calls
  `convertRgba`/`convertPhoto` directly. That is enough to prove the JS API reads
  a new option end to end — it caught nothing this time, but it is what says the
  page works rather than assuming it. It needs no Chrome. **That version should
  go in the repo**; the CDP driver can stay out.

## What keeps being true

- **The eleven pixel-art snapshots do not move.** Now survived the fitting
  restructure too, which is the change they were written for.
- **Fewer colours is not fewer regions.**
- **Measure, then look.**
- **A guarantee is only kept if the last stage keeps it too.** Held from the
  previous note, and now enforced by a test rather than by an argument.
- **The plan's specifics keep being wrong in the same way, and writing down *why*
  keeps catching them.** Eight for eight. New this session: a test written to
  assert the plausible thing failed, and the failure was the finding. Writing the
  assertion you expect to pass is how the plausible thing gets into the code.
